ETKINGDOM · LOCAL SIGNER

Your key stays local.

A first test wallet for macOS and Linux: encrypted account storage, native god1 and EVM addresses, GOD transfers, staking and G operations. Synthetic assets only.

This is a terminal signer with a browser workbench, not a wallet extension or a production wallet. Never use a personal private key, seed phrase or reused password. Windows private-file operations remain disabled until owner-only ACL acceptance.

Create and back up a disposable wallet

Use the reviewed local node build and an operator-reviewed complete testnet bundle. Set shell variables to your own absolute private paths and verified digest; none are preset here. The parent directory must be owner-only (0700). New files use 0600 and are never overwritten.

godd wallet create --wallet "$TEST_WALLET_FILE" \
  --bundle "$TEST_BUNDLE_FILE" --expected-bundle "$TEST_BUNDLE_SHA256"

Enter a new password twice in the private terminal. Passwords are hidden and cannot be supplied through arguments, environment values, files or pipes. Use a strong unique passphrase of 12 to 256 UTF-8 bytes. There is no password reset or recovery phrase: keep the encrypted file and its password safely backed up offline. The wallet is bound to this exact bundle.

Read the public account addresses

godd wallet address --wallet "$TEST_WALLET_FILE" \
  --bundle "$TEST_BUNDLE_FILE" --expected-bundle "$TEST_BUNDLE_SHA256" \
  --output "$TEST_ADDRESS_FILE"

The new private address file contains native god1 and compatible EVM encodings of the same account. Copy only the public address into the workbench, request manually reviewed test funding and verify the actual receipt and balance. Do not upload the wallet file.

Review and sign a test transaction

Use the workbench to query a fresh account sequence and download a GOD transfer or native operation request. Move it into your private directory and apply owner-only permissions. Review all fields before unlocking.

godd wallet sign --wallet "$TEST_WALLET_FILE" \
  --bundle "$TEST_BUNDLE_FILE" --expected-bundle "$TEST_BUNDLE_SHA256" \
  --request "$TEST_REQUEST_FILE" --output "$TEST_SIGNED_FILE"

The terminal displays the derived sender, chain identity, bundle digest, sequence, recipient or validator, amount and maximum fee in smallest units. Type SIGN only if they match your intent. Rejection creates no signed output. No private key is written in plaintext or entered in this page.

Signing is not submission. The operator submits the signed raw transaction to the reviewed observer RPC and then checks the explorer. GOD transfers use eth_sendRawTransaction and an EVM receipt; native operations use god_submitTransaction and the SDK result. Never treat SDK success as EVM success, retry blindly after an unknown submission outcome, or approve two transactions with the same shared sequence.

Test scope

The signer supports plain GOD transfers and six native operations: delegate, undelegate, claim settled G, transfer G, contribute GOD to reward liquidity and voluntary G redemption. It rejects arbitrary contract calls, bridge operations, key import and raw key export. Fees are capped at 0.01 synthetic GOD. The browser stays read-only and stores no account credentials.

Encryption uses fixed-work-factor scrypt and authenticated AES-256-GCM from pinned libraries. Local encryption does not protect a compromised computer, malware, a weak password or terminal recording. Memory clearing is best-effort, not a secure-erasure guarantee. Backup recovery, password rotation, a graphical signer, wallet extension and independent security review are separate milestones.
